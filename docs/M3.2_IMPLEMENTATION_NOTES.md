## Data model (additive, no migration)

`keywords`: `sources` (per source: sourceProperty, report, volume, difficulty, competition, position, url, metrics, timesSeen, firstSeenAt, lastSeenAt), `sourceList`, `seedRefs`, `grouping {rule, score, topicTitle}`, `excludedByRule {ruleId, rule, reason}`, `firstDiscoveredAt`, `lastDiscoveredAt`. Legacy top-level `source/volume/difficulty/metrics` still written (first source; refreshed only with non-null values). Rows written before M3.2 are lifted into `sources` on their next discovery.

`searchTopics`: `sources`, `sourceCount`, `seedRefs`, `qualification`, `qualificationReasons`, `preliminaryIntent`, `lastDiscoveredAt`. Legacy `source` kept.

No new collections, no new indexes (all new queries are equality-only), no rule changes.

## Decisions (ADR log)

1. **Seeds are rebuilt server-side; the client sends only a `seedKey`.** Guarantees discovery is driven by the confirmed Service Map, never by typed text. Cost: one extra Firestore read pass per run (free).
2. **Seeds are computed on demand, not persisted as a collection.** They are a pure function of confirmed services + profile + rules; persisting them would create a second source of truth. Lineage is persisted where it matters — on the raw queries and topics (`seedRefs`).
3. **Website/AI geography becomes a target only on ≥ 3 crawled pages** (`minPagesForServiceArea`, configurable). A single portfolio project is typically one page plus maybe a listing; three pages is a conservative, explainable proxy for "area the business presents as served". The owner can always declare an area in the profile.
4. **Script-mismatch guard.** "עיצוב פנים Caesarea" is not a real search; such combinations are skipped and explained rather than silently translated.
5. **Semrush split into seed and domain operations.** Previously every seed re-bought the domain's own rankings and competitors (~900 of ~2,100 units). Cache identity for seeds is phrase + database only, so the same phrase reached from two services is paid once.
6. **Grouping anchored on the topic title, exact match first, place guard.** Fixes drift (matching against accumulated tokens) and city collapse ("עיצוב פנים קיסריה" vs "…חיפה"). Still deterministic, still no stemming.
7. **A re-found query keeps its existing topic.** This is what makes owner exclusion durable for exact repeats; close variants that group into an excluded topic also stay excluded.
8. **Qualification never decides.** It is shown as hints with reasons; owner status is the only decision and discovery never writes it.
